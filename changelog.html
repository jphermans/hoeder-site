Hoeder A vault for the few things that must survive you.

Version history

What changed, in the order it changed. The version you are holding is in the app under Settings › About, which shows the current list; this page keeps all of it.

1.1 — build 2

The first version prepared for the App Store and Google Play.

Your vault is no longer in the folder iOS shares

The database and the photographs used to sit in Documents, which is the one folder an app can expose to the Files app — and it exposes all of it. Photographs and voice notes are not encrypted, so that would have made them readable without the PIN. They now live in the app's private directory, and only exported backups stay behind in Files → On My iPhone → Hoeder → Backups, which is what makes them findable in the first place. Existing vaults move on first launch: files first, then the paths in the database that point at them.

About

Settings › About is now a real screen: the version and build taken from the app itself rather than a constant, what changed, where your data is, and links to this page and to support.

Android

  • The lock screen always sets FLAG_SECURE, so the PIN pad cannot appear in a screenshot or in the task switcher, whatever the user's screenshot setting says.
  • The screen-overlay permission is stripped at build time: nothing to draw over other apps, and one fewer policy declaration.
  • Root, jailbreak and emulator state are read and reported in Settings › Security — with the honest caveat, in three languages, that anchor text stays encrypted while photographs and voice notes do not. It never blocks the app: anything rooted can hide from the check, and the protection is the encryption, not a boolean.

Unlocking

Deriving the vault key from the PIN was a single synchronous 120 000-iteration PBKDF2 loop, measured at 8.6 seconds on the device, because the JavaScript engine on device has no JIT. It now runs in the operating system's crypto and takes about 30 ms, with the iteration count unchanged and the derived bytes verified identical — the key is part of the vault format, so a one-byte difference would have made existing vaults unreadable.

Appearance

A real dark appearance (warm charcoal, never pure black) with three states in Settings: Automatic, Light, Dark. A test computes the WCAG contrast of every text pair in both palettes, which caught a caption colour at 3.31:1 — below the 4.5:1 minimum — now 4.76:1.

Splash

A launch screen that hands over to the app without the mark jumping size, held 1.4 s on a first run and 0.65 s afterwards, so the app does not appear to start reluctantly.

Demo content

Five anchors, one of each type, in the language you chose, with drawn rather than stock photographs: enough for a reviewer to see a populated vault in about a minute. Every demo anchor is a real anchor in the encrypted vault, and removing them can only ever touch the ids the app recorded when it created them.

1.0 — build 1

Internal build. Never distributed.

The vault itself: a six-digit PIN, a randomised AES-256-GCM vault key wrapped by a PBKDF2-derived key and held in the system keychain, optional biometric unlock, five anchor types with three layers each (now, care, handoff), photographs and 20-second voice notes, the Year Ring, export and import, a second steward, and Dutch, French and English throughout.
